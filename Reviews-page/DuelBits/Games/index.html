How Provably Fair Works at DuelBits

DuelBits describes its Originals as using a provably fair system that allows players to independently verify game results through cryptographic calculations.

According to DuelBits, the system combines three inputs to generate outcomes: a server seed, a client seed and a nonce.

Server Seed, Client Seed and Nonce

  • Server seed: A value generated by the DuelBits server. A SHA-256 hash is used to commit to the seed before it is revealed for verification.
  • Client seed: A value associated with the player that can be changed. It is combined with the server seed when generating outcomes.
  • Nonce: A counter that changes between bets, allowing different results to be generated when the seeds remain unchanged.

How Game Results Are Generated

DuelBits explains that these inputs are processed through an HMAC-SHA256 calculation. The resulting cryptographic output is converted into a game-specific outcome, such as a dice roll, Crash multiplier, Plinko result or Mines configuration.

Each game uses its own rules to transform the cryptographic output into a result. The verification calculation can be reproduced using the appropriate seeds, nonce and game algorithm.

How to Verify a DuelBits Original

  1. Open the game's fairness or verification information.
  2. Locate the relevant server seed hash, client seed and nonce.
  3. Obtain the revealed server seed when it becomes available.
  4. Verify that the revealed seed matches the previously displayed hash.
  5. Reproduce the cryptographic calculation using the game's published method.
  6. Compare the calculated result with the recorded game outcome.
